## Architecture and Implementation Boundaries

Use a single immutable contribution snapshot assembled at accepted reload. Its identity is exact structure ID, owner stage ID, action, source file/key, resolved priority, and accepted definition revision. It contains entry denial only for a missing owner where `entry_allowed` is omitted or false; `true` removes only that contribution. `prevent_block_break` and `prevent_block_place` add a missing-owner denial only when true. False or omitted optional flags contribute nothing and never produce ALLOW. Protection-only targets remain lookup candidates, but container, block, entity, and implicit interaction restrictions derive only from an active entry denial.

Both compilers must produce that same semantic contribution exactly once. `Schema4StageCompiler.applySimpleMetadata` must not decorate a convenience contribution a second time. Parsing rejects bad resource IDs, unsupported tag, namespace, or wildcard convenience selectors, non-Boolean flags, fractional or Boolean priority values, and signed-int32 overflow with a source key; rejected input leaves the prior accepted snapshot unchanged.

For player actions, select candidates matching structure, action, and missing owner stage, then join existing generic action rules in the actual `ConditionalLockEngine` path. Resolve priority in this exact order: explicit exact selector, explicit rule priority, category priority, stage priority, global default. Omitted `structures.rules.priority` retains inherited priority. An explicit zero is a rule-level value, while a fully unconfigured cascade is zero by default. Higher priority wins. Equal priority denial wins. Equally effective denials use stable owner-stage-ID then source-key provenance ordering, never registration order. A real explicit generic ALLOW above a matching convenience denial permits that static action. An ALLOW below or tied with the denial does not. `entry_allowed=true` must not simulate ALLOW.

Evaluate every overlapping structure. An allow for one structure cannot clear another active denial. Apply entry padding only to final denied structures that have active entry-denying contributions; use the maximum padding among equal highest-priority entry denials in one structure. Preserve `block_structure_entry`, creative and spectator bypasses, global and generic rule behavior, and provider/session sequencing. Provider or session acceptance remains subsequent and cannot be bypassed by missing static contributors, an unrelated ALLOW, or an empty entry contribution. Actorless explosion and spawn rules use structure-scoped OR only. They do not fabricate an actor, inspect player ownership, use player priority, or turn false into permit.

`InteractionCaptureManager` remains the one capture manager. Existing `interactions`, `progression`, `permissions`, and `editor` categories stay compatible. Add `structures` and `abilities` there, not a new recorder. Records are constructed lazily after filters pass and sent through the bounded queue without blocking tick or render threads. They record only configuration-relative source paths, bounded contributor summaries, and sanitized state. Client classes remain outside common and dedicated-server paths.
