## 3. Reproduction Protocol and Limitations

All records below use the same minimum artifact fixture: the downloaded 3.0.3 JAR, its embedded editor bundle where applicable, and the public issue report. Each decisive JAR extraction and hash command was repeated twice with identical results. A supported full runtime fixture was not available in this audit worktree for Curios, JEI plus EMI, browser operator editing, or client GUI-scale rendering.

Each issue record therefore identifies its evidence surface exactly:

| Evidence surface | Meaning |
| --- | --- |
| Packed class or packed JavaScript | A static inspection of the artifact that players install. It can verify a missing or incompatible shipped implementation surface, but not prove a complete player workflow. |
| Current source | A seam, regression-test, or follow-up implementation boundary. It is not proof that the 3.0.3 release behaved correctly. |
| Reporter evidence | The issue statement and supplied configuration or screenshot. It establishes the expected behavior and report scope, not a successful reproduction. |
| Unavailable runtime fixture | A required later test. Its absence is written as a limit, not inferred success. |
