are React and React DOM 19.1.1. Tests run through `vitest run`; DOM tests select `jsdom` with

### Exact caller and packaging checks

The registry archives for Vite 6.4.3, Browserslist 4.28.6, and
`@babel/helper-compilation-targets` 7.29.7 were read in memory from their lockfile URLs.
Each archive matched its locked SHA512 integrity value before source inspection. No package
code or lifecycle script was executed, and no archive was written or extracted to disk.

* Vite's `dist/node/chunks/dep-Dm0c1Wj2.js`, lines 43978 through 44060, supplies both `to`
  and `from` to PostCSS. When source maps are disabled, it returns CSS and an empty mapping
  representation. Disabling returned maps is not proof that the earlier parser reads no map.
* Browserslist's `index.js` imports the baseline mapping package, calls `env.getStat` during
  query resolution, and calls `getCompatibleVersions` for baseline queries. Babel's
  `lib/index.js` resolves nonempty browser target queries through Browserslist. These are
  actual transitive callers, not application imports inferred from package names.
* The pinned shared workflow at `d731214d860ad2422ab8956a5d337dfaec51f64a` installs the lock
  with `npm ci` and runs existing named scripts from its check list. For this package, that
  includes test and build. Its list does not include the local script named `check`; green
  workflow status therefore does not independently prove `npm run check` ran. Earlier local
  type checking remains separate evidence.
* The candidate contains four editor assets and no nested JARs or bundled classes from the
  alerted Maven package namespaces. Its editor JavaScript SHA256 is
  `2740008dbb6c3803f7fb0afc5ac74b31f58a0b09bb4e96ed1b334ef0f0ffa8e2`; its CSS SHA256 is
  `b91a98c1bc23525c4233b6d8d815536adca00a2469f8629376a82cb2bcd4b15b`.
  Neither asset contains the inspected mocker registration, baseline package, statistics
  filename, or source map annotation markers. This supports the source and hosting assessment;
  marker absence alone is not a bundle reachability proof.

### Commons Compress build path

The repository SPDX graph retrieved at 19:04:59 UTC records
`net.neoforged:neoform-runtime:2.0.18` depending on `io.codechicken:DiffPatch:2.0.0.36`,
which depends on `org.apache.commons:commons-compress:1.18`. It separately records 1.26.0
under `net.neoforged:minecraft-dependencies:1.21.1`. The export timestamp is not a new local
Gradle resolution or proof of the source revision represented by every submitted relationship.

The existing `DiffPatch-2.0.0.36-all.jar` has SHA256
`30d1ff26c112bf3a488e1e5a32a345f75ff0ef985c3315b2d987d607e7038580`. Archive inspection
found relocated Commons Compress classes under `io/codechicken/repack/`. Its actual
`ArchiveFormat` bytecode declares ZIP, TAR, TAR_XZ, TAR_GZIP, and TAR_BZIP2 readers and
writers. This proves an archive parser consumer in the tool, not an arbitrary game player
route to it. A newer unshaded classpath dependency cannot by itself patch these relocated
classes. Reconcile the exact vulnerable parser operations with the tool's accepted inputs
before selecting a disposition or any authorized remediation.

## Remaining work and cleanup

Next dependency work is to finish the DiffPatch archive input assessment, inspect the exact
logging configuration and optional provider consumers, and finish the LZ4 region and buffer
trust analysis. Any confirmed touched defect needs remediation and regression proof. Broader
transport admission, client robustness, real provider login and behavior, Brave acceptance,
combined gameplay, and final integration remain separate mandatory gates.

This bounded audit used read only API requests, source and archive reads, hash checks, and
short bytecode inspection subprocesses on `node-1`. An attempted inspection of a `.jar.cache`
sidecar correctly failed as a nonarchive; the followup read the actual `.jar` files. No
dependency installation, build, server, client, browser, extraction directory, or persistent
process was created. Registry bytes existed only in memory. The candidate, shared caches,
preexisting `run-248`, other worktrees, plan, goal, and cursor were preserved. Only this
required evidence document and its navigation references are retained.

The documentation validation accounted for each of the 33 alert numbers exactly once and
matched every advisory identifier, all five locked npm versions, the recorded input hashes,
and 107 local documentation link targets. Packaged JavaScript and CSS matched the retained
source assets byte for byte. Whitespace validation passed. The plan, goal, and cursor hashes
were unchanged, and no dependency installation or disposable audit resource remained.
